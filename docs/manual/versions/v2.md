# V2 — HISTORICAL en navegación, compatible en plataforma

## Estado

```text
language_version = 2.0.0
source_profile    = general_v2
status            = compatible
```

La página se clasifica como **HISTORICAL compatibility** en la navegación porque V2 ya no es el root current, pero su semántica sigue viva: las unidades `pure`, `recursive` y `effects` de Total-Core se escriben como fuente V2 y se compilan a Program IR V4.

## Superficie principal

V2 aporta:

- tipos exactos y construidos;
- funciones/generic functions;
- generic records;
- protocols/impls/associated types;
- bounded collections/iteration;
- contracted recursion;
- deterministic pure tasks;
- state/observations/effects;
- módulos/import/export;
- command intent en perfiles posteriores.

## Header

```text
script Demo version "2.0.0";
```

o:

```text
module My.Module version "2.0.0";
```

El frontend 3.1 no reescribe esto a `3.1.0`.

## Program IR V4

V2 es la fuente de las tres familias child actuales:

```text
pure      → Program IR V4 Pure
recursive → Program IR V4 Recursive
effects   → Program IR V4 Effects
```

Total-Core valida esos artefactos mediante sus validators originales.

## Compatibilidad aditiva

Una actualización de package/current root no cambia el significado de un script V2. La versión de fuente sigue siendo 2.0.0 y su semantic hash se deriva con reglas V2.

## Effects y mundo externo

V2 puede describir observaciones/state/commands, pero physical commit sigue detrás de capability/provider/grant. Total-Core no elimina esa frontera al embebir el child.

## Cuándo usar V2 hoy

Cuando escribes una unidad computacional child para Total-Core:

```text
unit Calc profile pure
unit Rec profile recursive
unit Sensors profile effects
```

la source correspondiente es V2 compatible.

## Qué NO hacer

- no uses `process ... 3.1.0` como header de child V2;
- no mezcles declarations pure/effects fuera de perfiles admitidos;
- no conviertas una API del host en función V2 sólo por ponerle un nombre;
- no supongas que V2 es deprecated/retirado: es una dependencia compatible current.
